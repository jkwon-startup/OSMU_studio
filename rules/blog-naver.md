# 블로그 규칙 — 네이버 상위노출 (C-Rank · DIA · DIA+ · 스마트블록)

> 적용: `osmu-blog-writer`, `osmu-reviewer`. 핵심 명제: 상위노출은 기술이 아니라 전략이다. 검색자의 **질의의도를 해소**해 체류시간과 클릭률을 올리는 글이 올라간다.

## 왜 올라가는가

검색자의 질의의도 해소 → 체류시간·클릭률 상승 → 가점 → 상위노출. 모든 전략의 종착점은 **독자 중심** 하나다.

| 로직 | 의미 | 글에서 할 일 |
|---|---|---|
| C-Rank | 블로그 자체의 신뢰도(주제 집중도·활동력) | 한 주제로 꾸준히 — 파이프라인이 매일 같은 영역의 글을 쌓는 이유 |
| DIA | 구조 + 제목·본문의 연관도 | 서론-본론-결론, 제목 형태소를 소제목으로 분산 |
| DIA+ | 질의의도 반영도 | 검색자가 진짜 궁금한 것을 본문에서 풀기 |

스마트블록은 블로그 지수의 영향을 거의 받지 않는다. **콘텐츠 구조와 질의의도 반영**이 지수보다 중요하므로 새 블로그도 진입할 수 있다.

## 글쓰기 전 (리서치 노트에서 가져온다)

- 메인 키워드 1개 + 서브 키워드 1~2개. 리서치 노트의 상위 글 제목에서 **겹치는 키워드**를 뽑는다(질의의도를 가장 잘 반영한 키워드).
- 상위 1~3위 글에 공통으로 쓰인 형태소, 타겟 키워드 옆에 함께 쓰인 단어를 본문에 자연스럽게 녹인다.
- 상위 글의 성격(정보성 / 후기성 / 상업성)을 따른다. 정보성 글에 후기성 키워드를 섞지 않는다. 혼합이면 정보 7 : 후기 3.
- 1위 글의 목차 구조를 참고하되 표현은 **문장 단위로 바꾼다**("콘드로이친 효능" → "콘드로이친, 어떤 효능이 있을까요?"). 유사 문서가 되면 안 된다.

## 제목

- **메인 키워드를 제목 맨 앞**에 둔다. 서브 키워드는 최대 1~2개, 질의의도 충돌 금지.
- **한글 25자 내외**(잘림 방지). 구체성·숫자 활용("…법 5가지").
- 조사·꾸밈어로 유사도를 낮추고, 키워드 사이를 의미로 연결한다.
- 특수문자 자제, 동일 키워드 반복 금지.
- **낚시성 제목 금지** — 본문과 불일치하면 즉시 이탈해 지수가 떨어진다.
- 카피라이터가 준 제목 후보 3개 중 위 규칙에 가장 맞는 것을 고른다. 후킹은 서브 역할이다.

## 서론 (첫 100자·첫 3~4문장이 승부처)

- **제목을 토씨 하나 틀리지 않게 그대로 1회** 삽입한다(서론 안에서, 의미 맥락에 맞게). 이 문장은 소제목으로 지정한다는 전제로 쓴다.
- 구성: 문제 제기 + 공감 + 궁금증 유발 + 메인 키워드. PAS(Problem → Agitate → Solve)의 가벼운 형태.
- 독자와의 약속: "이 글을 읽으면 → 이런 것을 얻는다".
- 필수 3요소: 왜 읽어야 하는가(필요성) / 무엇에 대한 글인가(논점) / 무엇을 얻는가(혜택).
- 서론 끝에 구분선(`---`).

## 본론

- **소제목으로 목차를 구조화**한다. 제목에 쓰인 단어(형태소)를 소제목에 나눠 쓴다.
  예) 제목 "상위노출에 필요한 3가지 알고리즘과 형태소" → 소제목 "상위노출에 필요한 3가지 알고리즘" / "알고리즘과 형태소"
- 핵심내용 5가지(03_key_points.md)를 소제목 축으로 삼는다. 순서는 독자의 질의의도 흐름(인지 → 고려 → 행동)에 맞춘다.
- **인용구**를 1~3개 쓴다. 인용구에 메인 키워드를 넣으면 스마트블록에 효과적이다.
- 키워드 반복: 메인 키워드는 초반에 2~3회, 이후 인용구·구분선을 이용해 후반에도 분산 배치. 파생 키워드(형태가 다른 표현)도 함께. 같은 문장을 반복해서 넣는 것은 어뷰징으로 본다.
- 통계는 "증명"이 아니라 "조명"으로 — 비유로 임팩트("10명 중 4명만 골문을 안다").
- 정보성 글도 미니 영웅의 여정으로: 독자 = 주인공, 문제 = 도전, 정보 = 무기, 해결책 = 보물.
- 관련 글 내부 링크 1개 자리를 표시한다(`[내부링크: 관련 글 제목]` — 설치자가 채운다). "함께 보면 좋은 글" 같은 상투 문구 금지.
- 장소·데이터가 있으면 표를 쓴다(지도·일정 도구는 발행 시 설치자가 넣는다).

## 결론

- 전체 요약 + 작성자의 생각·철학 + CTA. CTA는 대화체, 행동 동사, 혜택 명시.
- 반론을 예상해 1문장으로 미리 답한다(사전 반박).

## 문체 — 1인칭 · 공감 · 경험

AI가 글을 분석해도 클릭하고 머무는 건 사람이다. 진짜 경험이 담긴 1인칭 말투에 더 오래 머문다.

- 1인칭: "저는", "제가 겪은 바로는", "저희는 이렇게 합니다"
- 공감형: "혹시 이런 고민 있으셨나요?", "이런 분들께 특히 추천드립니다"
- 브랜드의 사람화: 브랜드 소개(config)의 이름·역할로 자기소개 1문장
- 경험 기반 예시: "실제로 이런 사례가 있었는데요" — **단, 리서치 노트나 브랜드 소개에 없는 사례·수치를 지어내지 않는다.** 경험이 필요한 자리는 `[작성자 경험 추가: …]`로 표시한다.
- 합니다체. 반복 표현 금지, 문단 끝 표현 다양화.

## 분량·형식

- **공백 제외 1,500자 이상**(권장 1,800~2,500자).
- 문단은 **4줄 이내**(모바일 기준). 한 문장이 2줄(모바일 4줄)을 넘으면 나눈다.
- 한 문단 안에서 같은 단어·조사 반복 지양.
- 강조는 문단별 핵심 문장 1개만(발행 시 볼드·형광 지정용으로 `**…**` 1개).
- 이모지 남발 금지. 특수문자 자제.
- 이미지 자리 5개를 `![이미지 N: 설명](images/blog_N.jpg)` 형식으로 본론 소제목마다 1개씩 표시한다(비주얼 디렉터가 채움). 서론에는 넣지 않는다.

## 페널티 요소 (금지)

- 과한 키워드 반복, 유사 문서
- 과대광고 표현: 유일한 · 최고 · 1위 · 100% 보장
- 홍보성 링크 남발
- 흔한 무료 이미지·캡처(이미지는 실사 생성본을 쓴다)

## 출력 형식 (`05_blog.draft.md`)

```
---
title: (확정 제목)
main_keyword: …
sub_keywords: [...]
intent_type: 정보성 | 후기성 | 혼합
---
(본문: 서론 → --- → 소제목 섹션들 → 결론)
```

## 발행 전 체크리스트 (검수 팀원이 확인)

- [ ] 제목 25자 내외, 메인 키워드 맨 앞, 낚시 아님
- [ ] 서론에 제목 문장 그대로 1회
- [ ] 공백 제외 1,500자 이상
- [ ] 소제목 3개 이상, 제목 형태소 분산
- [ ] 메인 키워드 초반 2~3회 + 후반 분산, 같은 문장 반복 없음
- [ ] 인용구 1개 이상, 내부링크 자리 1개, 이미지 자리 5개
- [ ] 문단 4줄 이내, 긴 문장 없음
- [ ] 1인칭·공감 화법, 지어낸 사례·수치 없음
- [ ] 과대광고 표현 0, 이모지 남발 없음
- [ ] 결론에 요약 + CTA
