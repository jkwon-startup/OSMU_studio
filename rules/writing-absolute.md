# 글쓰기 절대 규칙 — 작성 시점에 지키는 것

> 적용: 블로그·인스타·쓰레드·숏츠 내레이션을 쓰는 모든 팀원.
> 출처: im-not-ai(humanize-korean) 룰북에서 **빈도와 무관하게 항상 적용해도 안전한 규칙만** 골랐다.
> "한 문단에 3회 이상" 같은 빈도 조건 규칙은 여기 넣지 않는다 — 생성 시점에 넣으면 금지어처럼 작동해 글이 더 어색해진다. 그런 규칙은 작성 후 윤문 단계(humanize)가 처리한다.

## 항상 피한다

- **이중 피동**: "판단되어진다", "~지게 된다" → "판단된다", 능동으로.
- **이모지 남발**: 리스트 머리·헤딩·강조에 이모지 금지. 블로그·쓰레드 본문은 이모지 0, 인스타 캡션은 최대 2개.
- **의의 과장 종결**: "시사하는 바가 크다", "주목할 만하다", "매우 중요하다" → 삭제하거나 구체 결론으로.
- **열거 도입구**: "크게 세 가지로 나눌 수 있다", "다음과 같다" → 도입구 없이 바로 본론.
- **결말 공식**: "~할 때입니다", "~시점입니다", "~할 순간입니다", "이제 ~로 나아가야 합니다" → 구체 동사 단언으로.
- **분열문**: "필요한 것은 ~이다", "핵심은/관건은/답은 ~이다" → 주어-서술 직결("방향이 필요하다").
- **의인화 추상 주어**: "기술이 묻는다", "시대가 부른다" → 사람·기관 주어로.
- **광고성 영어 buzzword**: seamless·robust·leverage 류는 한국어로. 표준 기술 용어(API·prompt·token)는 원어 그대로.
- **한글+괄호 영어 병기 반복**: 첫 등장만 병기, 이후 한글만.
- **콜론 부제 헤딩 "X: Y" 반복**: 소제목은 단일 구 또는 질문 형태로.
- **문장마다 볼드**: 강조는 문단당 1개 이하.
- **대시(—) 부가설명 남발**: 쉼표·괄호·별도 문장으로.
- **연결어미 직후 쉼표**: "~하고, ~하며, ~지만," 뒤에 습관적으로 붙는 쉼표를 쓰지 않는다.
- **챗봇 프레임 문장**: "물론입니다", "다음은 ~입니다", "도움이 되셨길 바랍니다" 금지.

## 항상 지킨다

- **격식 일관**: 한 글 안에서 합니다체/해요체/반말을 섞지 않는다(쓰레드는 설정된 말투 하나로).
- **서법 보존**: 리서치가 "~로 보인다"면 글에서도 단정하지 않는다. 추측을 사실로 올리지 않는다.
- **고유명사·수치·날짜·출처**는 리서치 노트 그대로. 없는 수치·사례·인용을 만들지 않는다.
- **문장 길이 변주**: 짧은 문장과 긴 문장을 섞는다. 같은 종결어미 4문장 연속 금지.
- **진행형 남발 금지**: "~고 있다"는 실제 진행 중일 때만.
